Digibujo.

An attempt to digitalize the analog Bullet Journal method using Ruby on Rails and Hotwire. Capture first, triage later — and keep everything under your own roof.

01

Digital Bullet Journal

The analog method, on the web. Same rapid-logging philosophy, same migration rituals — powered by Ruby on Rails and Hotwire.

Ship the composer refactor
Review backlog before Friday
Add daily log timestamp

02

Capture, then curate

Brain-dump first, organise later. Daily logs, projects, and collections keep the noise navigable without slowing you down.

braindump → daylog → organize
03

Bullets, not just text

Four bulletable types tuned to what you're capturing — same composer, same hotkeys, same keyboard-driven flow.

Task completable
Note md · files · images
Event date range
Voice 60s memo
04

Keyboard-first

Every common intent — compose, navigate, pop, collect, complete, archive — has a hotkey, with hints surfaced inline.

⌘K open JK move C complete A archive
05

Publish what you want

Publish individual bullets to share them on the internet. Each one gets a short code and a clean public view — no login to read.

⌐ digibujo.dev /p/8x2k9
06

CLI & agent integration

Drive Digibujo from a terminal or from an AI agent. The same bullets, projects, and collections — programmable from outside the browser.

$ digibujo bullets new "Tune modal" --type task
created bullet #142
Work in progress
07

Webhooks

Subscribe to activity events and pipe them anywhere that speaks HTTP — automations, dashboards, your own scripts.

POST /webhooks/8x2k9
event: bullet.created id: 142, body: "Tune modal"
Work in progress
08

Self-host, open source

Totally open-source and ready for self-deployment with Kamal. Your data stays in your own SQLite databases — no external services, no Redis, no telemetry.

$ kamal deploy
released v0.4.2
